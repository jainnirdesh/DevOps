1. Introduction
This report describes the CI/CD workflow built in Lab 1: source code is kept in Git on GitHub, and Jenkins builds, tests and deploys it automatically.
2. Pipeline architecture
Developer -> git commit / push -> GitHub (devops-lab1, branch main)
                                        |
                       Jenkins polls every 5 min (Poll SCM)
                                        v
                 Jenkins on AWS EC2: Build -> Test -> Deploy
                                        |
                              success / failure message

Source control: Git, branches feature/farewell and feature/uppercase merged into main.
Server: Jenkins 2.568.2 on Ubuntu (AWS EC2), Java 21.
Application: small Python app (app.py) with a unit test (test_app.py).
Jobs: devops-lab1-freestyle (poll + shell build) and devops-lab1-pipeline (Jenkinsfile from SCM).

GitHub repository with branches and commit history
3. Pipeline stages
Build: print Python version and compile app.py (py_compile) to catch syntax errors.
Test: run unittest in verbose mode; a failure stops the pipeline before deploy.
Deploy: copy app.py to /tmp/deploy and run it from there.
Post: print a success or failure message.
pipeline {
    agent any
 
    stages {
        stage('Build') {
            steps {
                echo 'Building application...'
                sh 'python3 --version'
                sh 'python3 -m py_compile app.py'
                echo 'Build stage complete'
            }
        }
 
        stage('Test') {
            steps {
                echo 'Running unit tests...'
                sh 'python3 -m unittest test_app.py -v'
            }
        }
 
        stage('Deploy') {
            steps {
                echo 'Deploying application...'
                sh 'mkdir -p /tmp/deploy && cp app.py /tmp/deploy/'
                sh 'python3 /tmp/deploy/app.py'
                echo 'Deployed successfully'
            }
        }
    }
 
    post {
        success { echo 'Pipeline completed successfully' }
        failure { echo 'Pipeline failed' }
    }
}

5. Observations
Polling (every 5 minutes) is simple and needs no inbound webhook, but builds start with a delay of up to 5 minutes.
Keeping the Jenkinsfile in the repository versions the pipeline together with the code.
Disk/tmp space on the Jenkins node matters: a small /tmp took the built-in node offline until java.io.tmpdir was changed.
6. Conclusion
Every push to main can now be built, tested and deployed by Jenkins without manual steps.
